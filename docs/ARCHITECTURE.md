## 4. Core types (`src/types`)

```ts

export type Poisha = number;                       // always an integer

export interface MenuOption { id: OptionId; name: string; price: Poisha; uses: Record<IngredientId, number> }

  maxDistinct?: number; maxPerOption?: number; options: MenuOption[] }
export type Rule =
  | { id: string; type: 'requires'; option: OptionId; anyOf: OptionId[] }
  | { id: string; type: 'excludes'; option: OptionId; with: OptionId[] }
  | { id: string; type: 'overrideLimit'; option: OptionId; group: GroupId; max: number };
export type Promotion =
  | { id: string; type: 'cheapestFree'; group: GroupId; every: number }
  | { id: string; type: 'comboPercent'; percent: number; conditions: { group: GroupId; minUnits: number }[] }

  | { id: string; type: 'couponPercent'; code: string; percent: number; cap: Poisha; validBefore: string };

export type Config = Record<OptionId, number>;      // only options with qty > 0
```

## 5. Engine API (pure)

### money.ts
- `roundHalfUp(numerator: number, denominator: number): number` — integer math: `Math.floor((2*numerator + denominator) / (2*denominator))` for non-negative values.
- `percentOf(amount: Poisha, percent: number): Poisha` = `roundHalfUp(amount * percent, 100)`.
- `toWholeBdtPoisha(p: Poisha): Poisha` = `roundHalfUp(p, 100) * 100`.
- `formatBdt(p: Poisha): string` → `"1,659.50"`.

### validate.ts — `validate(config, groups, rules): Violation[]`
1. For each group: `total`, `distinct`, `max` = override max if an `overrideLimit` rule's option is selected for this group (if several, the smallest), else `group.max`.
2. Check min, max, step (`total % step !== 0`), maxDistinct, maxPerOption (per option). Collect **all**.
3. requires: option selected and none of `anyOf` selected → violation. excludes: option selected and any of `with` selected → violation (one per rule).
4. Messages use names from the menu, e.g. `"Eggs: total must be 2–6 in steps of 2 (you have 3)"`, `"Extras: max is 2 when Croissant is selected"`, `"Hollandaise requires Scrambled or Omelette"`, `"Tofu cannot be combined with Beef Bacon"`.
5. Unknown option id in config → violation `kind: 'max'`-like `unknown-option` (defensive, mention in DECISIONS extras).

### stock.ts
- `usageOf(config, menu, quantity): Record<IngredientId, number>`
- `sumUsage(a, b)`, `subtractUsage(a, b)`
- `availableStock(stock, sold, reservedLines): Record<IngredientId, number>`
- `shortagesFor(need, available, menu): Shortage[]` — fixture ingredient order; message `formatShortages()` → `"Short: 2 egg, 2 cheese"`.
- `optionHeadroom(menu, available, draft: Config, quantity): Record<OptionId, number | 'unlimited'>`
  → for each option: `min over its ingredients of floor((available − draftUsage) / (use × quantity))`.
- **Edit (net difference):** `availableForEdit = available + usageOf(oldItem.config, oldItem.quantity)` — only the item's own allocation is added back, so it can never release more than it holds.

### pricing.ts
- `priceUnit(config, menu): UnitBreakdown` → `{ base, optionsTotal, step1, cheapestFree: { freeUnits, discount }, step2, combo: { applied, discount }, unitPrice }` (field names follow promo *type*, not promo id)
  - P2: list every extra *unit* (option repeated qty times) sorted by price ascending; free = sum of the cheapest `floor(units / every)`.
  - P1: if every condition's group-unit total ≥ `minUnits` → `discount = percentOf(step2, percent)`; `unitPrice = step2 − discount`.
- `priceCart(cart: CartLineInput[], menu, promos, serverTime, couponCode?: string | null): CartBreakdown`
  → `{ lines: [{ id, unit: UnitBreakdown, quantity, lineTotal }], subtotal, candidates: [{ id, amount, eligible, reason }],
       appliedDiscount: { id, amount } | null, coupon: CouponResult, discountedSubtotal, vat, payableExact, payable }`
  - C2 eligible only if `couponCode` matches (case-insensitive, trimmed) **and** `isStrictlyBefore(serverTime, validBefore, shop.timeZone)`.
  - Pick the larger eligible amount; tie → first id in `shop.cartDiscountTieBreak`.
  - `vat = percentOf(discountedSubtotal, vatPercent)`; `payableExact = discountedSubtotal + vat`; `payable = toWholeBdtPoisha(payableExact)`.
  - `CouponResult = { entered: string | null, applied: boolean, status: 'applied'|'not_entered'|'invalid_code'|'expired_time'|'lost_to_better_discount', reason: string }`.

Hand check (must pass): B unit = 75500 → P1 7550 → **67950**. TC-06 VAT = percentOf(150950, 5) = roundHalfUp(754750, 100) = **7548**; payable 158498 → **158500**.

## 6. Mock server

### State (`localStorage["sob:v1"]`)
```ts
interface ServerState {
  schemaVersion: 1;
  seeded: boolean;
  cart: { version: number; couponCode: string | null; items: CartItem[] };
  orders: StoredOrder[];                       // seed + checkout
  idempotency: Record<string, { status: number; body: unknown; savedAt: number }>;
}
interface CartItem { id: string; config: Config; quantity: number; createdAt: number; expiresAt: number; version: number }
```
- A cart item **is** its reservation. "Active" = `expiresAt > serverNow()`. Expired items stay in the cart as read-only until removed; they hold no stock.
- `sold` = usage of all orders with `source: 'checkout'`. Seed orders are history (`source: 'seed'`) and do not reduce stock.
- `withState(fn)`: `const s = structuredClone(loadState()); const result = fn(s); saveState(s); return result;` — if `fn` throws, nothing is saved (atomic).
- Menu is not stored in state; it always comes from the fixture file.

### Clock & chaos
- `clock.ts`: `let skewMs = 90_000; export const serverNow = () => Date.now() + skewMs;` plus `__setSkewForTests()`.
- `chaos.ts`: `{ priceFailRate: 0.15, reserveFailNext: false, random: Math.random }`, setters for tests and a small "Dev tools" toggle in the UI ("Fail next reserve") to demo TC-14. In tests chaos is **off** unless a test turns it on.
- Latency (MSW `delay()`): `/api/price` random 200–1500 ms; other routes 100–300 ms. Tests run with latency 0 (an env flag in handlers).

### Endpoints (every response includes `serverTime`)
| Method & path | Body | Success | Errors |
|---|---|---|---|
| GET `/api/menu` | – | `{ menu, serverTime }` | – |
| GET `/api/stock` | – | `{ stock, sold, reserved, available, serverTime }` | – |
| POST `/api/price` | `{ requestId, config, quantity }` | `{ requestId, breakdown: UnitBreakdown, lineTotal, violations, serverTime }` | 503 `PRICE_UNAVAILABLE` (chaos 15%) |
| GET `/api/cart` | – | `{ cart: { version, couponCode, items: CartItemView[] }, totals: CartBreakdown, serverTime }` | – |
| POST `/api/cart/items` | `{ idempotencyKey, config, quantity }` | 201 `{ item, cart, serverTime }` | 422 `INVALID_CONFIG {violations}`, 409 `OUT_OF_STOCK {shortages, available}`, 503 `RESERVE_FAILED` |
| PUT `/api/cart/items/:id` | `{ idempotencyKey, config, quantity, itemVersion }` | 200 `{ item, cart, serverTime }` | 404, 410 `EXPIRED`, 409 `OUT_OF_STOCK {shortages, available}`, 409 `VERSION_CONFLICT`, 422 |
| DELETE `/api/cart/items/:id` | – | 200 `{ cart, serverTime }` | 404 |
| PUT `/api/cart/coupon` | `{ code: string | null }` | 200 `{ cart, totals, serverTime }` | – |
| POST `/api/checkout` | `{ idempotencyKey, paymentMethod: 'card'|'bkash'|'cash' }` | 201 `{ order, serverTime }` | 409 `CART_EMPTY` (no active items), 422 |
| GET `/api/orders` | – | `{ orders: StoredOrder[], serverTime }` | – |

- `CartItemView` = item + `status: 'active'|'expired'` + `unit` breakdown + `lineTotal`.
- Cart totals (`GET /api/cart`) are always **re-priced at current server time** (price is not locked in the cart — D2 suggestion: lock at checkout).
- Idempotency: before doing work, `recall(key)` → if found, return the saved response unchanged. After success, `remember(key, response)`. Failed responses are **not** remembered (so Retry with the same key works).
- Add item: validate → `available` → `shortagesFor(usage × qty)` → chaos "mid-way" point (after building the new item on the copy, before commit) → push item → `expiresAt = serverNow() + ttl`.
- Edit item: 410 if expired; `availableForEdit` (net difference) → shortages → replace config/quantity in the same state copy → `version + 1`. Keeps the original `expiresAt` (suggestion; record in DECISIONS extras).
- Checkout: active items only; `priceCart` at `serverNow()` with cart coupon → `buildStoredOrder` → push to `orders` → **empty cart** → save once. Same idempotency key twice → same order.

### Seed loading (`seed.ts`)
- On the first request where `state.seeded === false`: read `orders.seed.json`, `normalizeSeedOrder()` each (adapter for the seed's real field names — inspect the file in Step 1), price with `priceCart(lines, menu, promos, Date.parse(createdAt), couponCode)`, store with `source: 'seed'`, set `seeded = true`.
- If a seed line uses an unknown option id → keep the order but mark `pricingWarnings` (never crash).

## 7. Browser side

### Server clock (`api/serverClock.ts`)
`updateOffset(serverTime)` is called by `client.ts` on every response: `offset = serverTime − Date.now()`. `serverNow() = Date.now() + offset`. Countdown text = `expiresAt − serverNow()`. When it reaches 0 → refetch cart.

### Price preview (`usePricePreview`) — TC-12
1. `debounced = useDebouncedValue({config, quantity}, 300)`.
2. On change: `latestId += 1`; abort previous `AbortController`; POST with `requestId = latestId`.
3. On response: if `response.requestId !== latestId` → ignore (stale). Two protections: abort **and** id check.
4. On failure: keep config, set `status = 'error'`, show **Retry** (re-sends the same config).
5. States: `idle | loading | ready | error`. Show "updating…" while loading but keep the last good price visibly marked as stale.

### Add to Cart — TC-13, TC-14
- One idempotency key per draft attempt (`useRef`), reused on double/triple click **and** on Retry; a new key only after success or after the config changes.
- Button disabled while: violations exist, any shortage, request pending. Disabled reason shown next to it.
- On 409 show `Short: …`; on 503 show "Could not reserve. Your selection is kept." + Retry.

### Stock display
- `useStock` refetches after every mutation, on window focus, and every 5 s (so the other tab's changes show up).
- Each option shows `+N left` (or "∞") from `optionHeadroom`; disabled at 0 with a reason.

### Cart
- Countdown per item from server time; expired → grey, "Reservation expired — remove or add again", Edit hidden, Remove enabled.
- Edit opens the item in the builder (edit mode: headroom uses net difference). Save = PUT. D1/D3 handling per DECISIONS.
- Totals panel shows full breakdown: subtotal, each discount candidate (applied / why not), VAT, payable.
- Coupon input + payment method select + Pay (idempotency key; disabled while pending).

### Orders tab
- Table of all orders (seed + new) with payable; **Download orders.json** → `Blob` of `JSON.stringify(orders, null, 2)`.

## 8. Assistant (Part F)

### Tools (C2 suggestion — user confirms in DECISIONS)
| Question | Function | Inputs | Output |
|---|---|---|---|
| How many orders? | `getOrderCount` | `{ date?: 'YYYY-MM-DD' }` | `{ count }` |
| Total revenue? | `getTotalRevenue` | `{ date? }` | `{ revenuePoisha, revenueBdt }` |
| Best-selling option (units)? | `getBestSellingOptions` | `{ limit?: number }` | `{ ranking: [{ optionId, name, units }], ties: boolean }` |
| Revenue by payment method? | `getRevenueByPaymentMethod` | – | `{ methods: [{ method, orders, revenueBdt }] }` |
| Average order value? | `getAverageOrderValue` | – | `{ averageBdt, orders }` |
| How many got the coupon? | `getCouponUsage` | – | `{ entered, applied, notApplied: [{ orderId, status, reason }] }` |
| Orders on a date? | `getOrdersOnDate` | `{ date }` | `{ date, count, revenueBdt, orders: [{ id, time, payableBdt, paymentMethod }] }` |

- Units = `line.quantity × option qty`. Dates use `shop.timeZone`.
- `stats.ts` functions are pure `(orders, menu, args) => result`. `tools.ts` executor **fetches `/api/orders` fresh on every tool call** → new checkouts show immediately (TC-18) and changed data is reflected (TC-19).
- No customer tool exists (D5). System prompt: only use tool results; if no tool fits, say the data does not contain it; never invent names or numbers.

### Gemini loop (`gemini.ts`)
`POST https://generativelanguage.googleapis.com/v1beta/models/${MODEL}:generateContent?key=${KEY}` with `systemInstruction`, `contents`, `tools: [{ functionDeclarations }]`.
1. Send user question → if response has `functionCall` → run tool → append `functionResponse` → call again. Max 3 rounds.
2. Return the final text plus the tool name used (shown small under the answer, e.g. "via getOrderCount").
3. `MODEL` constant in `assistant/config.ts` = current Flash model name from Google AI Studio (verify the exact name when creating the key).

### Errors (`errors.ts`)
- No key → "Gemini key missing: add VITE_GEMINI_API_KEY to .env.local and restart `npm run dev`."
- 400/401/403 with key error → "Gemini key is invalid."
- 429 → "Gemini free quota reached. Wait a minute and try again."
- `TypeError` from fetch / offline → "Network error: could not reach Gemini."

### Tests
- `stats.test.ts` against the priced seed orders (values cross-checked with ANSWERS).
- `gemini.test.ts` mocks `fetch`: first reply = functionCall, second = text. Check the tool was run locally and raw orders were **never** in the request body.

## 10. Testing strategy
- **Engine unit tests**: every rule type, rounding edge cases (x.5 poisha), headroom, shortages, alt fixture.
- **Acceptance tests** (`src/test/acceptance`): one file per TC group, test names start with the TC id (`it('TC-06 …')`).
  - TC-01…11: pure engine + server functions with fixed `serverTime` (Dhaka 10:59:59 = `2026-11-25T04:59:59Z`).
  - TC-12…14: RTL + MSW node server; control latency per request to force out-of-order responses; chaos flag for the mid-way failure.
  - TC-15: `vi.useFakeTimers()` + clock skew 90 s; check the countdown text and expiry follow server time.
  - TC-16, 17: server functions + `saveState/loadState` round-trip (simulated refresh) + export JSON parse.
  - TC-18…20: mocked Gemini returning function calls; real stats; checkout in between.
- `test/builders.ts` builds A/B/C configs by **option name** from the fixture so tests read like the brief.
- `npm test` runs everything. `npm run answers` prints Q1–Q8.
